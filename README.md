# 基于大模型的智能文档问答系统 (RAG-based Document QA)

这是一个基于大语言模型（LLM）的检索增强生成（RAG）本地文档问答项目。项目从零手写基础链路起步，逐步演进为具备工程化防御能力的应用系统。

## 📌 核心功能 (Features)
- [x] **基础链路跑通**：实现本地文本读取、文本切块、Prompt 拼装与大模型 API 调用。
- [x] **工程化防御**：引入 `try...except` 异常处理机制，实现 API 调用失败重试（最多 3 次）与降级兜底策略，防止网络抖动导致程序崩溃。
- [ ] **语义检索升级**：引入 LangChain 与 FAISS 向量库，解决传统硬切块导致的上下文截断问题，实现基于语义的 Top-K 召回。（进行中）
- [ ] **多轮对话记忆**：基于 JSON/SQLite 实现历史对话持久化，支持多轮上下文问答。
- [ ] **Web 界面交互**：基于 FastAPI 与 Gradio 封装后端接口与前端页面。

## 🛠️ 技术栈 (Tech Stack)
- 语言：Python 3.11+
- 大模型：DeepSeek API (兼容 OpenAI SDK)
- 框架与库：OpenAI (基础调用) / LangChain (规划中) / FAISS (规划中) / FastAPI (规划中)

## 🚀 踩坑与优化记录 (Engineering Notes)
*记录在开发过程中遇到的实际问题及解决思路，这也是本项目的核心思考：*

1. **硬切块导致上下文截断**：初期采用固定长度切块（500字），导致句子被从中间切断，模型检索到的上下文不完整。**后续优化**：计划引入带重叠（Overlap）的语义切分策略。
2. **关键词匹配的性能瓶颈**：尝试用字符串匹配进行检索，发现无法解决多实体检索问题，且全量遍历存在 O(N) 性能瓶颈。**后续优化**：引入向量数据库（FAISS）实现高效的语义检索。
3. **API 网络抖动**：模型调用易受网络影响。**已解决**：增加超时限制（`timeout`）与最多 3 次的循环重试，失败后执行降级输出，保障服务鲁棒性。
